## Known lab traps (read first)

1. The checker reads image names. Use the lab's exact images: `k8s.gcr.io/hpa-example`, `gcr.io/google-samples/hello-app:1.0`, `k8s.gcr.io/pause`. Newer registry addresses run fine but score only partial points.
2. `kubectl get pods -w` and the load generator (`kubectl run -i --tty`) never return. Here they're replaced with commands that finish by themselves.
3. VPA and the cluster updates are mostly waiting. Run them at the same time in two Cloud Shell tabs. The whole lab fits in about 30 minutes.
4. The checker lags. If a check shows 0 right after a successful step, wait 30–60 seconds and click again.

## Task 2 – Vertical Pod Autoscaling (Tab 1, about 5–8 minutes)

```bash
cd ~
kubectl create deployment hello-server --image=gcr.io/google-samples/hello-app:1.0
kubectl set resources deployment hello-server --requests=cpu=450m
cat > hello-vpa.yaml <<'EOF'
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler
metadata:
  name: hello-server-vpa
spec:
  targetRef:
    apiVersion: "apps/v1"
    kind:       Deployment
    name:       hello-server
  updatePolicy:
    updateMode: "Off"
EOF
kubectl apply -f hello-vpa.yaml
until kubectl describe vpa hello-server-vpa | grep -q "Container Recommendations"; do echo "waiting for VPA recommendation..."; sleep 20; done
kubectl describe vpa hello-server-vpa | sed -n "/Container Recommendations/,/Events/p"
sed -i 's/Off/Auto/g' hello-vpa.yaml
kubectl apply -f hello-vpa.yaml
kubectl scale deployment hello-server --replicas=2
timeout 150 kubectl get pods -w -l app=hello-server
kubectl get deployment hello-server -o wide
```

The recommendation shows Target CPU around 25m. During the watch, hello-server pods go to Terminating or Pending, which means VPA is resizing them. The last line shows image gcr.io/google-samples/hello-app:1.0. You can ignore the "UpdateMode Auto is deprecated" warning.

## Task 8 – Pause pods (Tab 1, after Task 2 finishes)

```bash
cd ~
cat > pause-pod.yaml <<'EOF'
---
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: overprovisioning
value: -1
globalDefault: false
description: "Priority class used by overprovisioning."
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: overprovisioning
  namespace: kube-system
spec:
  replicas: 1
  selector:
    matchLabels:
      run: overprovisioning
  template:
    metadata:
      labels:
        run: overprovisioning
    spec:
      priorityClassName: overprovisioning
      containers:
      - name: reserve-resources
        image: k8s.gcr.io/pause
        resources:
          requests:
            cpu: 1
            memory: 4Gi
EOF
kubectl apply -f pause-pod.yaml
kubectl get priorityclass overprovisioning
kubectl get pods -n kube-system -l run=overprovisioning
```

The PriorityClass is listed, and the pause pod shows Pending or Running. Pending means NAP is adding a node, which takes 2–4 minutes.
