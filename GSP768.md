## Task 2 – Vertical Pod Autoscaling

Block 1 – confirm VPA is on, deploy hello-server, and set a 450m CPU request:

```bash
gcloud container clusters describe scaling-demo --zone=`cat ~/zone` | grep ^verticalPodAutoscaling -A 1
kubectl create deployment hello-server --image=us-docker.pkg.dev/google-samples/containers/gke/hello-app:1.0
kubectl set resources deployment hello-server --requests=cpu=450m
kubectl rollout status deployment hello-server --timeout=120s
kubectl describe pod hello-server | sed -n "/^Containers:/,/^Conditions:/p" | grep -A 2 Requests
```

The first line should say enabled: true, and Requests should show cpu: 450m.

Block 2 – create the VPA in Off mode and wait for a recommendation:

```bash
cd ~
cat > hello-vpa.yaml <<'EOF'
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler
metadata:
  name: hello-server-vpa
spec:
  targetRef:
    apiVersion: "apps/v1"
    kind:       Deployment
    name:       hello-server
  updatePolicy:
    updateMode: "Off"
EOF
kubectl apply -f hello-vpa.yaml
until kubectl describe vpa hello-server-vpa | grep -q "Container Recommendations"; do echo "waiting for VPA recommendation..."; sleep 20; done
kubectl describe vpa hello-server-vpa | sed -n "/Container Recommendations/,/Events/p"
```

You should see Lower Bound, Target, Uncapped Target and Upper Bound. Target CPU is usually around 25m.

Block 3 – switch to Auto, scale to 2 replicas, and watch VPA recreate the pods (stops by itself after 2.5 minutes):

```bash
cd ~
sed -i 's/Off/Auto/g' hello-vpa.yaml
kubectl apply -f hello-vpa.yaml
kubectl scale deployment hello-server --replicas=2
timeout 150 kubectl get pods -w -l app=hello-server
```

You should see hello-server pods go to Terminating or Pending and then come back. That's VPA resizing them.

## Task 8 – Optimize larger loads (pause pods)

```bash
cd ~
cat > pause-pod.yaml <<'EOF'
---
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: overprovisioning
value: -1
globalDefault: false
description: "Priority class used by overprovisioning."
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: overprovisioning
  namespace: kube-system
spec:
  replicas: 1
  selector:
    matchLabels:
      run: overprovisioning
  template:
    metadata:
      labels:
        run: overprovisioning
    spec:
      priorityClassName: overprovisioning
      containers:
      - name: reserve-resources
        image: k8s.gcr.io/pause
        resources:
          requests:
            cpu: 1
            memory: 4Gi
EOF
kubectl apply -f pause-pod.yaml
kubectl get priorityclass overprovisioning
kubectl get deployment overprovisioning -n kube-system
```

The PriorityClass and the deployment should both be listed. The pause pod can stay Pending for 2–4 minutes while the autoscaler adds a node, often in a new nap- node pool.

```bash
for i in 1 2 3 4 5 6 7 8; do kubectl get pods -n kube-system -l run=overprovisioning --no-headers; sleep 30; done
kubectl get nodes
```
